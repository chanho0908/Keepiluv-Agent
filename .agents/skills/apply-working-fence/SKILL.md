# Apply Working Fence

코드 변경을 시작하기 전에 다음 순서로 작업 범위를 고정한다.

1. **먼저 생각하기**
   - 불확실한 가정과 여러 해석을 숨기지 않는다.
   - 결과를 바꾸는 모호함은 사용자에게 확인한다.
   - 더 단순한 방법이 있으면 먼저 제시한다.
2. **단순하게 해결하기**
   - 현재 요청에 필요한 코드만 작성한다.
   - 한 번만 쓰는 추상화, 요청하지 않은 유연성, 불가능한 상황을 위한 방어 코드는 만들지 않는다.
3. **관련된 부분만 바꾸기**
   - 모든 변경 줄을 사용자 요청과 연결할 수 있어야 한다.
   - 주변 코드의 형식, 주석, 오래된 코드를 임의로 정리하지 않는다.
   - 이번 변경으로 새로 사용되지 않게 된 항목만 정리한다.
4. **완료 조건으로 검증하기**
   - 작업을 테스트나 명령으로 확인할 수 있는 목표로 바꾼다.
   - 여러 단계라면 각 단계와 확인 방법을 짧게 적는다.
   - 완료 조건이 충족될 때까지 수정과 검증을 반복한다.

구체적인 좋은 예와 피해야 할 예는 [references/examples.md](references/examples.md)를 필요한 항목만 읽어 적용한다.

이 규칙은 신중함을 속도보다 우선한다. 한 줄 수정처럼 명백한 작업, 명시적인 실험, 사용자가 미래 확장성을 직접 요청한 경우에는 작업 성격에 맞게 간소화한다.
